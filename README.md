# ZineMaker

写真のZINE・写真集・SNS用の組写真を組む macOS アプリ。
写真は現像済みの前提で、**レイアウトと書き出しだけ**に集中する。

## できること

**2つのモードを切り替えて使う。** レイアウトは比率を保ったまま移し替わるので、
同じ組写真を 4:5 と 1:1 と 9:16 で出す、といったことがそのままできる。

| | ZINE・写真集 | 組写真（SNS） |
|---|---|---|
| 単位 | mm | px |
| 判型 | A5 / B5 / A4 / 文庫 / 正方形 / 任意 | **任意のアスペクト比**（1:1 4:5 3:4 2:3 9:16 3:2 4:3 16:9 1.91:1／数値直接入力） |
| ページ | 見開き・ノド・塗り足し・トンボ | 1枚ずつのボード |
| 主な出力 | 入稿用PDF | JPEG / PNG / AVIF / HEIC / TIFF / JPEG XL |

### 入力

**JPEG XL / AVIF / TIFF（16bit）/ JPEG / PNG / HEIC** — すべて ImageIO 経由でシステムの
デコーダをそのまま使うので、追加ライブラリがない。EXIF の回転も自動で反映する。

### 色の指定

書き出しごとに色空間とガンマを選べる。画面は Display P3 で見ていても、配る先に合わせて変換して出す。

| | 使いどころ |
|---|---|
| sRGB | web・SNS・どこでも安全 |
| Display P3 / Adobe RGB / ProPhoto | 広色域の画面・印刷前提のRGB・編集用 |
| グレースケール | モノクロ |
| **CMYK** | **印刷所入稿。無彩色は K 版だけに落とす** |

CMYK では写真・文字・図形をすべて変換する。**r≈g≈b の色は C=M=Y=0 の墨1色**にするので、
黒い文字が4色刷りにならない（実測: 黒→K100、50%グレー→K50、有彩色→4色分解）。

ガンマは 0.6〜1.6。刷ると沈む、といった最後の微調整に使う。

### 出力

| 形式 | 備考 |
|---|---|
| PDF | 入稿用（TrimBox / BleedBox 付き）、単ページ／見開き、写真は JPEG ストリームで埋め込み |
| JPEG / PNG / TIFF / AVIF / HEIC | ImageIO で直接書き出し |
| JPEG XL | macOS は JXL を**読めるが書けない**ため、`cjxl` があるときだけ有効になる（`brew install jpeg-xl`） |

サイズは「長辺のpx」か「幅×高さの直接指定」。比率が違う場合は地色を背景に中央へ収める。

### 写真集の型

黒地に写真を浮かせる写真集でよく使われる組み方を、そのまま雛形にしてある。

| 型 | 中身 |
|---|---|
| 1枚＋撮影データ | 中央に写真、下に `Day : … / Location : …` `Gear : … / Lens : … / Setting : …` の2行 |
| 縦組み見出し＋写真 | 片側に地色の帯と縦組みの大見出し、縦罫、残りに写真 |
| 縦2枚 / 見出し＋横2枚 | 複数枚とそれぞれの撮影データ |
| 1枚＋地名 | 写真の角に小さなラベル |
| 章扉 / あとがき | 第N章・大見出し・罫線・項目一覧 |
| 大＋小の重ね | 大きな写真の角に小さな写真を、紙色の縁を付けて重ねる |
| 帯状に3枚 | 細長く切った3枚を横に並べ、下に罫を1本通す |
| 大1＋小3 | 左に大きく1枚、右に小さく3枚 |
| 片側裁ち落とし | 片ページ全面、対向に小さく1枚 |
| 全面＋リボン | 全面写真に撮影地のリボンを重ねる |
| 全面＋大きな文字 | 全面写真に見出しを重ねる（暗幕＋罫線付き） |

**ノンブル**は全ページ共通要素として1度置けば、以降のページに自動で入る。
`{page.digits}` を使うと写真集でよく見る「1桁ずつ縦に積む」形になる。

### 撮影地を EXIF から出す

EXIF の GPS 座標を CLGeocoder で地名に直し、`PhotoAsset` に保存する。
同じ座標はまとめて1回しか問い合わせないので、21枚でも数回で済む。
一度引けば `.zine` に残るので、以後はオフラインでも出る。

| 記号 | 例 |
|---|---|
| `{place}` | 目黒区 青葉台 |
| `{place.full}` | 東京都目黒区青葉台2丁目 |
| `{gps}` / `{gps.dms}` | 35.65023, 139.69627 ／ N35°39'01" E139°41'47" |
| `{direction}` | 北北東（レンズの方角） |
| `{where}` | GPS があればそれ、無ければ IPTC |

### 文字の下に敷く地

テキストに **べた帯 / リボン / 下線** を敷ける。
写真の上に載せる見出しやキャプションが、明暗に関係なく読めるようになる。
リボンは両端が V 字に切り込まれた帯で、図形としても置ける。

### 図形と罫線

四角・楕円・罫線・菱形・三角。塗り／枠線／不透明度／角丸を個別に指定できる。
見出しの下線、サイドバーの区切り、表紙の半透明な図形といった、
写真集のほぼ全ページで使う要素はこれで組める。

### レイアウトを細かく作る

- **定規**（mm / px）と、そこからドラッグして引く**カスタムガイド**
- **段組みグリッド**（段 × 行 × 段間）。セルの端にも吸着し、「段組みに合わせる」で枠をセルにぴったり揃えられる
- **回転**（ハンドル／数値／90°ずつ。⇧ で15°刻み）。回転した枠も正しく掴めて、掴んでいない角が動かないようにリサイズされる
- **重なり順パネル** — 並び替え、ロック、非表示、名前の変更
- **繰り返し配置**（ステップ＆リピート）と、**数値で間隔をそろえる**
- 整列・等間隔配置、角丸、枠線
- **写真の比率を保つ** — 入れておくと、枠の大きさをどう変えても写真の形のまま。
  切り取られない。写真を置いた枠には最初から入っている（型に流し込んだ枠は形が決まっているので入らない）
- **吸着（マグネット）** — 動かすときも大きさを変えるときも、仕上がり線・余白・ノド・ガイド・
  段組み・ほかの要素に吸い付き、吸着した線が出る。大きさを変えるときは掴んでいる辺だけが寄るので、
  反対側の角は動かない。⌃ を押している間だけ切れる

### その場で打ち込む・持ち出す

- 文字枠は**キャンバス上でそのまま打てる**。ダブルクリック、選択中にもう一度クリック、または ⏎ で入る。
  紙の色を地にして実寸・実書体で表示するので、行数や収まりを見ながら打てる。⎋ で取り消し、外をクリックで確定。
  EXIF から差し込んでいる文字は取り違えないよう編集を断り、どこで直すかを下に出す。
- **コピー・切り取り・貼り付け**は判型をまたげる。A5 の誌面から正方形の組写真へ貼ると、
  位置は仕上がり枠に対する比率で移り、文字の級数も紙の大きさの比で調整される。
  参照している写真は実体ごと運ぶので、貼った先で写真が抜けない。同じ写真を二度貼っても増えない。

### 書き出す前の点検（プリフライト）

⌘⇧P、またはツールバーの「点検」。刷ってから気づく類の事故を先に出す。

| 出るもの | 何を見ているか |
|---|---|
| 写真が見つからない／枠が空 | 参照切れ、中身のない枠 |
| 解像度が足りない | 置いた大きさに対する実効 dpi（既定 300） |
| 文字が枠に入りきらない | Core Text で組んで、入らなかった分があるか |
| 文字が小さすぎる | 6pt 未満 |
| 裁ち落としが足りない | 紙の端に接する写真が塗り足しまで伸びているか |
| 文字が仕上がり線の外 | 裁ち落ちる位置に文字がないか |
| ノドに近すぎる | 綴じで隠れる位置に文字や顔がないか |

指摘をクリックするとそのページへ飛ぶ。印刷向けの項目（裁ち落とし・ノド）は切り替えで隠せる。

### ポートフォリオ

送付用PDF・製本・対面プレゼン向けの作品集を組むための仕組み。

- **ページ種別** — 作品 / 表紙 / ステートメント / プロフィール / 作品一覧 / 中扉。
  通し番号は作品ページだけに振られる
- **シリーズ（章）** — ページをまとめ、中扉と一覧に反映する
- **EXIF から自動キャプション** — 撮影日・カメラ・レンズ・焦点距離・絞り・シャッター・ISO・
  IPTC の作品名や撮影地を差し込む。**写真に紐づくので、あとで写真を差し替えても文面が追従する**
- **作品一覧の自動生成** — `{index}` を置いたページに、作品番号順の一覧が組まれる。
  1行の書き方は書類ごとに決められる（`settings.indexTemplate`）。点数が多くて1ページに入らないときは
  `{index.1}` と `{index.2}` で前半・後半に分けて、見開きの左右へ流せる

差し込みは `{plate}` `{camera}` `{doc.author}` のような記号で書く。
値が空のときは区切り記号と空行が自動で掃除されるので、
`{camera} / {lens}` でレンズ情報が無くても " / " が残らない。

### テンプレート

テンプレートから選ぶと、枠を作って写真を順に流し込む。**「全部を流し込む」**を選べば、
トレイの写真をテンプレートを繰り返しながら必要な数のページへ自動で分ける。

型の形とは別に、レイアウトの画面で**外側の余白**と**写真の間の隙間**をそれぞれ外せる。
両方外すと、紙の端まで写真だけで埋まる。SNS の組写真でよく見る、横帯を積んだ形がこれで組める。
誌面で外側の余白を外すと塗り足しまで伸びるので、そのまま裁ち落としになる。
この2つは誌面と組写真で別々に覚えておく。

形は 1枚／上下2分割／左右2分割／上大・下小／上小・下大／縦3段／3段・中央大／横3列／
上1・下2／上2・下1／大＋小／2×2／縦4段／3×2／2×3／左大＋右4／3×3 など。

### 配布についての注意

App Sandbox は**切ってある**。`PhotoAsset` は security-scoped bookmark を持っているので
写真の参照自体はサンドボックス下でも解決できるが、entitlement を入れての検証がまだ済んでいない。

## 操作

| | |
|---|---|
| ドラッグ | 移動（仕上がり線・余白・ノド・ガイド・段組み・他要素に吸着。吸着した線が出る） |
| ⇧ドラッグ | 縦横どちらかに固定して移動 |
| ⌃ドラッグ | 吸着を一時的に切る |
| ⇧クリック | 選択に追加／解除 |
| 何もない所からドラッグ | 範囲選択 |
| ハンドル | リサイズ（⇧ で比率を保つ、⌥ で中心から） |
| 回転ハンドル | 回転（⇧ で15°刻み） |
| 定規からドラッグ | ガイドを引く（定規へ戻すと消える） |
| ⌘ドラッグ | 枠内で写真を移動（トリミング） |
| ⌥スクロール | 枠内で写真を拡大縮小 |
| ⌘スクロール／ピンチ | ズーム |
| ⌥ドラッグ | 画面のパン |
| 矢印キー | 1pt 移動（⇧で10pt） |
| 文字枠をダブルクリック／選択中にもう一度クリック | その場で打ち込む（⎋ で取り消し、外をクリックで確定） |
| ⌘C / ⌘X / ⌘V | 要素のコピー・切り取り・貼り付け（別の作品へも。写真ごと運ぶ） |
| 右クリック | その場のメニュー（ここに貼り付け・複製・最前面／最背面） |
| トレイの写真をダブルクリック | 選択中の枠に入れる |
| トレイからキャンバスへドラッグ | その枠に入れる／新しい枠として置く（新しい枠は写真の形になるので切り取られない） |

Finder から写真を直接ドラッグ&ドロップできる。`.zine` はダブルクリックで開く。

## 設計の要点

### 描画経路は1本しかない

`CanvasRenderer.draw(_:settings:assets:in:options:)` が誌面を描く唯一の場所で、
画面・PDF・書き出し画像・サイドバーのサムネイル・書き出しプレビューは
**どの `CGContext` を渡すか** だけが違う。

```
画面          → NSView の CGContext
入稿PDF       → CGPDFContext
書き出し画像   → CGBitmapContext
サムネイル     → CGBitmapContext
```

プレビューと書き出しで別のエンジンを使うとレイアウトがズレる（特に日本語の行分割で顕著に出る）。
Core Graphics / Core Text はどちらの出力先でも同じコードが通るので、この問題が構造的に起きない。

**新しい要素タイプを足すときも、描画は必ず `CanvasRenderer` に集約すること。**

### 座標系

内部はすべて **pt (1/72 inch) の y-up**。Core Graphics と PDF に揃えてあるので変換が要らない。
組写真モードでは 1pt = 1px として扱い、書き出し時に目標ピクセル数へスケールする。
mm / px は入出力の表示だけ（`Pt.fromMM` / `Pt.toMM`）。
インスペクタの Y だけは「紙の上端からの距離」に直して見せている。

px で持つと 350dpi 入稿のときに作り直しになるので、ここは変えないこと。

### 画像解像度

書き出し時は「配置サイズ × 目標DPI」から必要画素数を逆算して、その分だけデコードする
(`CanvasRenderer.ImageQuality.output`)。33MP の写真を 40mm の枠に置いても PDF は肥大化しない。
元画像を超える解像度は要求しない（水増ししない）。

インスペクタは配置時の実効 dpi を表示し、ZINEモードで 300dpi を切ると警告色になる。

画面用のデコードは非同期で、終わったら `ImageStore.didLoad` を投げて再描画させる。
33MP を数十枚並べても操作が止まらないのはこのため。

### 雛形の文字は実データを入れて収まりを見る

Core Text は枠に1行も入らない大きさだと**何も描かない**（欠けるのではなく消える）。
雛形を作るときは `CanvasRenderer.fittedFontSize` で入る大きさまで詰めている。

差し込みキャプションは、記号のままだと短いので収まって見えてしまう。
`fittedFontSize` には必ず写真の実データを入れた `Scene` を渡すこと。

### オフスクリーン描画は同期でデコードする

画面用のデコードは非同期（終わったら再描画）だが、サムネイルや書き出しプレビューのような
一度きりの描画では写真が間に合わず空になる。`CanvasRenderer.rasterize` は
`.screen` を指定されても内部で同期デコードに読み替えている。

### 保存ファイルの前方互換

**Swift の自動生成デコーダは、キーが無いときにプロパティの初期値へ落ちてくれず `keyNotFound` を投げる。**
つまり `DocSettings` にフィールドを1つ足すだけで、それ以前に保存した .zine が全部開けなくなる。

`DocSettings` / `ImageFrame` / `TextFrame` / `Artboard` / `ZineFile` は自前の `init(from:)` を持ち、
`KeyedDecodingContainer.value(_:_:)` を通して「無ければ初期値」で読む。
**値を持つ型にフィールドを足すときは、必ずこのデコーダにも1行足すこと。**

### 差し込みキャプションの解決

`CanvasRenderer.draw` は `Scene`（写真の実体＋差し込みの文脈）を受け取る。
文脈は `DocumentContext` がドキュメント全体を一度走査して作り、作品番号・ページ番号・
作品一覧の行をまとめて持つ。ページ単位で作ると作品番号が決まらないため。

テキストフレームは `template` を持つと差し込みになり、`text` ではなく解決後の文字列が描かれる。
`freezeCaption` でいつでも固定テキストに戻せる。

### PDF への写真の埋め込み

Core Graphics は既定でビットマップを可逆圧縮して埋め込むので、そのままだと
A5見開き12ページで **244MB** になる。`ImageStore.jpegBacked` で JPEG データ由来の
`CGImage` を作って描くと、Quartz が DCTDecode ストリームとしてそのまま埋め込むため
**27MB** に収まる（実測）。書き出しシートの「可逆圧縮で埋め込む」で切り替えられる。

### 入稿PDFのボックス

| | 単ページ | 見開き |
|---|---|---|
| MediaBox | 仕上がり + 塗り足し4辺 | 同左（見開き幅） |
| TrimBox | 仕上がり | 仕上がり（見開き幅） |
| BleedBox | MediaBox と同じ | 同左 |

単ページ出力ではノド側にも塗り足しを付けるので、隣ページの絵柄がそのまま回り込む。
組写真モードでは塗り足しもトンボもなく、ボードのピクセル数のまま等倍で出る。
