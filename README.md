# ZineMaker

写真のZINE・写真集・SNS用の組写真を組む macOS アプリ。
写真は現像済みの前提で、**レイアウトと書き出しだけ**に集中する。

## できること

**2つのモードを切り替えて使う。** レイアウトは比率を保ったまま移し替わるので、
同じ組写真を 4:5 と 1:1 と 9:16 で出す、といったことがそのままできる。

| | ZINE・写真集 | 組写真（SNS） |
|---|---|---|
| 単位 | mm | px |
| 判型 | A5 / B5 / A4 / 文庫 / 正方形 / 任意 | **任意のアスペクト比**（1:1 4:5 3:4 2:3 9:16 3:2 4:3 16:9 1.91:1／数値直接入力） |
| ページ | 見開き・ノド・塗り足し・トンボ | 1枚ずつのボード |
| 主な出力 | 入稿用PDF | JPEG / PNG / AVIF / HEIC / TIFF / JPEG XL |

### 入力

**JPEG XL / AVIF / TIFF（16bit）/ JPEG / PNG / HEIC** — すべて ImageIO 経由でシステムの
デコーダをそのまま使うので、追加ライブラリがない。EXIF の回転も自動で反映する。

### 出力

| 形式 | 備考 |
|---|---|
| PDF | 入稿用（TrimBox / BleedBox 付き）、単ページ／見開き、写真は JPEG ストリームで埋め込み |
| JPEG / PNG / TIFF / AVIF / HEIC | ImageIO で直接書き出し |
| JPEG XL | macOS は JXL を**読めるが書けない**ため、`cjxl` があるときだけ有効になる（`brew install jpeg-xl`） |

サイズは「長辺のpx」か「幅×高さの直接指定」。比率が違う場合は地色を背景に中央へ収める。

### レイアウトを細かく作る

- **定規**（mm / px）と、そこからドラッグして引く**カスタムガイド**
- **段組みグリッド**（段 × 行 × 段間）。セルの端にも吸着し、「段組みに合わせる」で枠をセルにぴったり揃えられる
- **回転**（ハンドル／数値／90°ずつ。⇧ で15°刻み）。回転した枠も正しく掴めて、掴んでいない角が動かないようにリサイズされる
- **重なり順パネル** — 並び替え、ロック、非表示、名前の変更
- **繰り返し配置**（ステップ＆リピート）と、**数値で間隔をそろえる**
- 整列・等間隔配置、角丸、枠線

### テンプレート

15種類のテンプレート（1枚／2〜4分割／大＋小／2×2／3×3／左大＋右4 など）から選ぶと、
枠を作って写真を順に流し込む。**「全部を流し込む」**を選べば、トレイの写真を
テンプレートを繰り返しながら必要な数のページへ自動で分ける。

## ビルドと起動

```bash
./Scripts/bundle.sh release && open .build/ZineMaker.app
```

`swift build` だけでも実行ファイルはできるが、NSOpenPanel とウィンドウのアクティベーションに
Info.plist が要るため、通常は `bundle.sh` で .app に包んで起動する。
Xcode で `Package.swift` を直接開いても動く。

## 操作

| | |
|---|---|
| ドラッグ | 移動（仕上がり線・余白・ノド・ガイド・段組み・他要素に吸着。吸着した線が出る） |
| ⇧ドラッグ | 縦横どちらかに固定して移動 |
| ⌃ドラッグ | 吸着を一時的に切る |
| ⇧クリック | 選択に追加／解除 |
| 何もない所からドラッグ | 範囲選択 |
| ハンドル | リサイズ（⇧ で比率を保つ、⌥ で中心から） |
| 回転ハンドル | 回転（⇧ で15°刻み） |
| 定規からドラッグ | ガイドを引く（定規へ戻すと消える） |
| ⌘ドラッグ | 枠内で写真を移動（トリミング） |
| ⌥スクロール | 枠内で写真を拡大縮小 |
| ⌘スクロール／ピンチ | ズーム |
| ⌥ドラッグ | 画面のパン |
| 矢印キー | 1pt 移動（⇧で10pt） |
| トレイの写真をダブルクリック | 選択中の枠に入れる |
| トレイからキャンバスへドラッグ | その枠に入れる／新しい枠として置く |

Finder から写真を直接ドラッグ&ドロップできる。`.zine` はダブルクリックで開く。

## 設計の要点

### 描画経路は1本しかない

`CanvasRenderer.draw(_:settings:assets:in:options:)` が誌面を描く唯一の場所で、
画面・PDF・書き出し画像・サイドバーのサムネイル・書き出しプレビューは
**どの `CGContext` を渡すか** だけが違う。

```
画面          → NSView の CGContext
入稿PDF       → CGPDFContext
書き出し画像   → CGBitmapContext
サムネイル     → CGBitmapContext
```

プレビューと書き出しで別のエンジンを使うとレイアウトがズレる（特に日本語の行分割で顕著に出る）。
Core Graphics / Core Text はどちらの出力先でも同じコードが通るので、この問題が構造的に起きない。

**新しい要素タイプを足すときも、描画は必ず `CanvasRenderer` に集約すること。**

### 座標系

内部はすべて **pt (1/72 inch) の y-up**。Core Graphics と PDF に揃えてあるので変換が要らない。
組写真モードでは 1pt = 1px として扱い、書き出し時に目標ピクセル数へスケールする。
mm / px は入出力の表示だけ（`Pt.fromMM` / `Pt.toMM`）。
インスペクタの Y だけは「紙の上端からの距離」に直して見せている。

px で持つと 350dpi 入稿のときに作り直しになるので、ここは変えないこと。

### 画像解像度

書き出し時は「配置サイズ × 目標DPI」から必要画素数を逆算して、その分だけデコードする
(`CanvasRenderer.ImageQuality.output`)。33MP の写真を 40mm の枠に置いても PDF は肥大化しない。
元画像を超える解像度は要求しない（水増ししない）。

インスペクタは配置時の実効 dpi を表示し、ZINEモードで 300dpi を切ると警告色になる。

画面用のデコードは非同期で、終わったら `ImageStore.didLoad` を投げて再描画させる。
33MP を数十枚並べても操作が止まらないのはこのため。

### 保存ファイルの前方互換

**Swift の自動生成デコーダは、キーが無いときにプロパティの初期値へ落ちてくれず `keyNotFound` を投げる。**
つまり `DocSettings` にフィールドを1つ足すだけで、それ以前に保存した .zine が全部開けなくなる。

`DocSettings` / `ImageFrame` / `TextFrame` / `Artboard` / `ZineFile` は自前の `init(from:)` を持ち、
`KeyedDecodingContainer.value(_:_:)` を通して「無ければ初期値」で読む。
**値を持つ型にフィールドを足すときは、必ずこのデコーダにも1行足すこと。**

### PDF への写真の埋め込み

Core Graphics は既定でビットマップを可逆圧縮して埋め込むので、そのままだと
A5見開き12ページで **244MB** になる。`ImageStore.jpegBacked` で JPEG データ由来の
`CGImage` を作って描くと、Quartz が DCTDecode ストリームとしてそのまま埋め込むため
**27MB** に収まる（実測）。書き出しシートの「可逆圧縮で埋め込む」で切り替えられる。

### 入稿PDFのボックス

| | 単ページ | 見開き |
|---|---|---|
| MediaBox | 仕上がり + 塗り足し4辺 | 同左（見開き幅） |
| TrimBox | 仕上がり | 仕上がり（見開き幅） |
| BleedBox | MediaBox と同じ | 同左 |

単ページ出力ではノド側にも塗り足しを付けるので、隣ページの絵柄がそのまま回り込む。
組写真モードでは塗り足しもトンボもなく、ボードのピクセル数のまま等倍で出る。
